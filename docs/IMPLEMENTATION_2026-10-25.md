# Проверяемый отчёт — 25 октября 2026

## Аудит и точка начала

Проект уже содержит React 19 + TypeScript + Vite, TanStack Query, Zustand,
React Router, i18next, Tailwind и FastAPI + SQLAlchemy + Alembic + JWT/Argon2.
Работа продолжена в существующей архитектуре. База по умолчанию SQLite;
PostgreSQL поддержан инфраструктурой проекта. Авторизация не заменялась.

До начала работы было множество изменённых и новых файлов. Они сохранены;
этот отчёт отделяет выполненную сейчас работу от предыдущей реализации.
Во время работы также появились изменения CatalogMenu.tsx, которые не сделаны
этой задачей и не перезаписывались.

Найдены локальные изображения и `docs/design/stitch-home-original.png`. Этот
сохранённый референс — тёмный AUTO UNIVERSE с красными акцентами. Прикреплённого
пользователем исходного изображения AUTO PRIME в доступном сообщении нет.
Точное визуальное соответствие AUTO PRIME не подтверждено.

Блокирующее расхождение: существующий `black-silver.css` не был импортирован,
а DESIGN.md описывал светлую красную витрину. Теперь чёрно-серебряный слой включён.

## Реальные изменения этой сессии

- Подключён существующий Black & Silver CSS ко всем страницам приложения.
- Тёмная тема стала начальной; убраны переключатели, которые не могли менять
  фиксированное чёрно-серебряное оформление. Обновлён theme-color документа.
- Создана отдельная адаптивная аналитическая панель с графитовой боковой
  навигацией, серебряными KPI, графиком Recharts и доступной таблицей данных.
- Разделы: обзор, продажи, товары/склад, покупатели, заказы, финансы.
- Диапазон дат, 7/30/90 дней, дневной/недельный/месячный масштаб,
  предшествующий период, выбор категории/переход из категории, CSV, сортировка.
- Реальные разрезы категорий/брендов, лидеры, остатки, товары без продаж,
  новые/повторные покупатели, скидки, доставка, отмены и возвраты.
- По истории статусов считаются достигнутые этапы и часы от создания до этапа.
- Новый агрегирующий FastAPI endpoint с правами и периодами по Душанбе.
- Сохранён старый dashboard API; миграции БД не потребовались.
- Добавлены честное состояние оплаты заказа и интерфейс будущего провайдера.
  Неподключённый провайдер возвращает 503, не принимает webhook и не создаёт
  успешную оплату. Страница заказа получает описание состояния через API.
- Формулы и ограничения описаны в `ANALYTICS_METRICS.md`.

## Запуск

В двух PowerShell-терминалах из корня проекта:

```powershell
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

```powershell
cd frontend
npm.cmd run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

В этой сессии оба процесса запущены. Сайт: http://127.0.0.1:5173/;
аналитика: http://127.0.0.1:5173/cockpit; API: http://127.0.0.1:8000/docs.
Для аналитики нужна существующая учётная запись с `view_statistics`.
Тестовых сотрудников/заказов в рабочей базе эта сессия не создавала.

На новом окружении используйте backend/.env.example, настройте DATABASE_URL и
случайный JWT_SECRET, установите requirements в venv и выполните Alembic перед
запуском; frontend — `npm.cmd ci`. Не публикуйте .env. В текущем экземпляре
миграции не требуются именно для внесённых изменений аналитики/оплаты.

Проверки из соответствующих папок:

```powershell
# backend
.\.venv\Scripts\python.exe -m pytest -q --tb=short -p no:cacheprovider
# frontend
npm.cmd run build
npm.cmd run lint
```
