# Warm Luxury Glass V4 — реализация и проверка

27 октября 2026. Работа выполнена в существующем React/TypeScript/Vite-проекте.
Production не публиковался; серверные конфигурации, API, миграции и пользовательская база не изменялись в ходе этой задачи.

## Выполненные этапы

1. **Аудит.** Изучены маршруты, компоненты, клиент API, авторизация, корзина, подбор автомобиля, checkout и роли. Сохранены существующие незакоммиченные изменения. Снимок до работы: `.runtime/warm-glass-before-20261027.zip` (включает frontend/src, frontend/index.html, прежний DESIGN.md). Создание ветки заблокировано правами записи в `.git`; архив служит точкой восстановления.
2. **Основа дизайна.** Единые семантические токены Warm Ivory / Champagne, материалы glass/elevated/inset, границы, свет, тени, радиусы, интервалы и длительности. Светлая тема по умолчанию для нового посещения, сохранённая тёмная тема учитывается. Ранний выбор темы в HTML уменьшает вспышку неверной темы при загрузке.
3. **Dashboard.** Стеклянные sidebar, header, KPI, график и таблицы; адаптация Recharts к обеим темам; сворачивание sidebar с доступными названиями кнопок; переключение темы; удалён дублированный фильтр сравнения. Добавлены поиск по названию/SKU и пагинация по 8 позиций в уже полученном серверном отчёте. Сортировка, периоды, фильтры и CSV сохранены. На мобильном фильтры раскрываются отдельной кнопкой.
4. **Витрина.** Стеклянная навигация, кремовая панель поверх существующей автомобильной фотографии, мягкие золотые действия, материалы каталога, карточек, фильтров, брендов и секций подбора.
5. **Commerce и аккаунт.** Общие материалы карточек корзины, итогов заказа, checkout, профиля, Admin, пустых состояний и форм входа. Исправлена композиция иллюстративной панели авторизации. Для пустого сравнения, корзины и checkout добавлена возможность заголовка h1 без нарушения h2 во вложенных пустых секциях.
6. **Мобильная адаптация.** Сохранена нижняя навигация, доступны все разделы аналитики; таблицы прокручиваются внутри контейнера; элементы управления имеют размеры для касания.
7. **Полировка и доступность.** Отрегулирован контраст стекла поверх фотографии; график поднят выше операционных предупреждений. Сохранены focus states, семантические таблицы данных графика, native controls, обработка ошибок, prefers-reduced-motion. Добавлены непрозрачные fallback-поверхности без backdrop-filter.
8. **Проверки.** TypeScript + production build, 11 frontend-тестов, 74 backend-теста, ручная проверка в Chrome и снимки экрана.

## Ограничения

- Во вложении был только текст: фотографии Glassy Dashboard V4/V3 не переданы. Точное визуальное соответствие этим изображениям проверить невозможно; реализовано описанное направление Warm Luxury Glass.
- Использованы качественные изображения из проекта. Для отсутствующих фотографий конкретных SKU сохранены честные подписи об иллюстрации категории; неподтверждённые фотографии, рейтинги и совместимость не добавлялись.
- Конверсия, подтверждённая выручка, удержание и другие недоступные метрики не выдумывались. Существующая аналитика различает стоимость заказов и подтверждённую оплату.
- Реальная оплата, отправка заказа и изменение рабочих данных не выполнялись. Внешние платёжные и production-интеграции требуют проверки в их штатной среде. Функции административного редактирования не прогонялись с записью в рабочую базу.

## Локальный запуск

Обычный запуск с вашим настроенным FastAPI:

```powershell
# В backend, с доступным Python-окружением проекта
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
# В другом терминале, из frontend
npm.cmd run dev -- --host 127.0.0.1
```

Открыть `http://127.0.0.1:5173/`; аналитика — `/cockpit`, управление — `/admin`. Доступ определяется существующими ролями и серверными правами.

Для воспроизведения изолированной QA-среды из корня проекта:

```powershell
.\backend\.venv\Scripts\python.exe .runtime/warm-glass-qa.py
```

Скрипт использует только `.runtime/warm-glass-qa-20261027.db`, стандартный demo seed проекта и localhost:8000. Не запускайте его одновременно с другим API на этом порту. Используемый тестовый администратор — стандартная запись demo seed из `backend/app/seed.py`; она не создавалась в рабочей базе.

Проверки из frontend: `npm.cmd test`, `npm.cmd run build`. Проверки из backend: `.\.venv\Scripts\python.exe -m pytest -q` (тесты создают отдельную временную SQLite-базу).
